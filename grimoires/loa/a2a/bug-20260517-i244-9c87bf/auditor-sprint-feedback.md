## Injection-Surface Walkthrough

### `_parse_iso8601_to_epoch` (validate.sh:464-503)

| Vector | Safe? | Reasoning |
|---|---|---|
| `python3 -c '<script>' "$ts"` | ✓ | `$ts` passed as `sys.argv[1]` — NOT shell-interpolated into the script. Python's `datetime.fromisoformat` raises on malformed input, wrapped in try/except, returns sys.exit(1). |
| `gdate -d "$ts" +%s` | ✓ | `$ts` passed as argv to `date`, not eval'd. Quoted preventing word-split. |
| `date -j -u -f "..." "$ts" +%s` | ✓ | Same as above. |
| `date -u -d "$ts" +%s` | ✓ | Same as above. |
| Fall-through to `epoch=0` | ✓ | Same as pre-fix behavior — false-positive freshness signal but no exploit. |

**Source of `$ts`**: `sed -n '/<!-- ground-truth-meta/,/-->/p' "$FILE" | grep "generated_at:" | awk '{print $2}'` — comes from BUTTERFREEZONE.md, which is project-local content. If an attacker can edit that file, they already have write access to the project. Trust boundary: operator-owned.

## Findings

### Finding M-1 — MEDIUM (non-blocking) — yq install via `latest` URL in CI workflow

**Location**: `.github/workflows/bats-tests.yml:48-50`

```yaml
- name: Install yq (Linux)
  if: runner.os == 'Linux'
  run: |
    sudo wget -q -O /usr/local/bin/yq https://github.com/mikefarah/yq/releases/latest/download/yq_linux_amd64
    sudo chmod +x /usr/local/bin/yq
```

**Issue**: Downloads yq binary from GitHub releases at `latest` tag, executed as root via `sudo`. No sha256 verification, no version pin. If Mike Farah's GitHub account or the yq release pipeline is compromised, a malicious binary could be substituted and execute with root privileges in CI.

**Impact**: CI runner compromise. CI has no production secrets attached (workflow permissions: `contents: read`), so impact is contained to runner-side mischief (test poisoning, log exfiltration).

**Risk Level**: MEDIUM. Standard practice for installing yq, but the standard practice has known supply-chain exposure (CWE-829: Inclusion of Functionality from Untrusted Control Sphere).

**Recommendation** (follow-up, not blocking this PR):
```yaml
- name: Install yq (Linux)
  if: runner.os == 'Linux'
  env:
    YQ_VERSION: v4.45.1  # pin
    YQ_SHA256: <known-good-hash>
  run: |
    sudo curl -sSL -o /usr/local/bin/yq \
      "https://github.com/mikefarah/yq/releases/download/${YQ_VERSION}/yq_linux_amd64"
    echo "${YQ_SHA256}  /usr/local/bin/yq" | sha256sum -c -
    sudo chmod +x /usr/local/bin/yq
```

**Disposition**: Surface to operator. Same pattern is used in many of the repo's existing workflows, so this is consistent-with-prior-art rather than a new regression. Accept for this PR; recommend a follow-up sweep that pins all binary-from-URL installs across `.github/workflows/`.

### Finding L-1 — LOW (non-blocking) — Markdown injection via `relationship` field

**Location**: `.claude/scripts/butterfreezone-construct-gen.sh:163-168`

**Issue**: The new jq filter renders `relationship: "<text>"` directly into CONSTRUCT-README.md without escaping. A malicious construct.yaml could inject:
- Newlines: `relationship: "a\nb"` → mangled bullet
- Links: `relationship: "[click](https://evil)"` → live link
- Headers: `relationship: "\n## fake-section"` → fake section in readme

**Impact**: Cosmetic. CONSTRUCT-README.md is a static markdown file rendered on GitHub — same trust model as the YAML source. No exec, no XSS (markdown link clicks are user-initiated; GitHub has its own URL safety).

**Risk Level**: LOW. Pack authors already control their own readme via PR; this is not a privilege escalation.

**Recommendation** (follow-up): Strip `\n` and `\r` from `.relationship` before interpolation, OR add a `construct-validate.sh` check rejecting multi-line relationship values. Both are paranoia hardening, not vulnerability closure.

**Disposition**: Accept for this PR. Cosmetic-only.

### Finding I-1 — INFORMATIONAL — Implicit `python3` dependency in validate.sh

**Location**: `.claude/scripts/butterfreezone-validate.sh:471-483`

**Issue**: Comment claims "python3 — already a Loa dependency", but no init-time check enforces this. On a stripped-down env without python3, the chain falls through to BSD `date -j` or GNU `date -d`, which may also be missing. Falls open to `epoch=0` → false freshness signal.

**Severity**: INFO (already documented in `engineer-feedback.md` §Assumption Challenged).

**Disposition**: No action required for this PR. Consider documenting dependencies in `.loa.config.yaml.example` or validator `--help` as a follow-up.

### Finding I-2 — INFORMATIONAL — Silent fallback in skill-pack routing

**Location**: `.claude/scripts/butterfreezone-gen.sh:2327-2341`

**Issue**: When routing predicate fails (yq missing OR `construct-gen` non-executable), user intent is silently denied. Not a security issue — produces wrong output, not a compromise.

**Severity**: INFO (already documented in `engineer-feedback.md` §Concern 2).

**Disposition**: No action required for this PR.

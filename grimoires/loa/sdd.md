## 1. System overview

### 1.1 Topology

**[GROUNDED · README + apps/api/src + packages/]**
Turbo monorepo with four workspaces:
- `apps/api` — Hono + Node.js HTTP API (port 3000, `/v1` mount)
- `apps/docs` — VitePress documentation site (`constructs.network`)
- `packages/shared` — TypeScript types + Zod validation + categories
- `packages/loa-registry` — CLI plugin for the Loa CLI (`constructs` bin)

### 1.2 Component diagram

See `grimoires/loa/reality/architecture-overview.md` for the full ASCII diagram.

```
GitHub (construct-* repos)
   │ webhooks + git-sync
   ▼
apps/api (Hono /v1 · 22 routers · ~94 handlers)
   ├── Postgres (30 Drizzle tables)
   ├── Upstash Redis (rate-limit + cache)
   ├── R2 (S3 protocol, presigned URLs)
   ├── Stripe + Stripe Connect
   ├── Resend (email)
   ├── Sentry
   ├── Dynamic Labs (wallet JWT)
   └── GitHub OAuth + GitHub Apps
       ▲
       │ uses /v1
   ┌───┴────────────────────┐
   │ apps/docs (VitePress)  │
   │ packages/loa-registry  │ ← CLI bin: `constructs`
   └────────────────────────┘
```

## 5. Auth design

### 5.1 Token types

**[GROUNDED · config/env.ts]**

| Token | Algo | Role |
|-------|------|------|
| User session | RS256 (preferred) / HS256 (deprecated) | Email-pw + OAuth login |
| Wallet JWT | RS256 (Dynamic Labs JWKS) | wallet-bound auth (cycle-039) |
| API key | bearer (DB-stored) | Programmatic access (cycle-040) |
| Operational token | bearer (env-supplied) | Service-to-service |

### 5.2 RS256 helpers

**[GROUNDED · config/env.ts:163-214]**

```ts
getPrivateKey()      // base64-decoded PEM
getPublicKey()       // base64-decoded PEM
getKeyId()           // JWT_KEY_ID (default 'key-2026-02')
isRS256Available()   // both keys present
isHS256Available()   // JWT_SECRET present (legacy)
```

### 5.3 Production guards

**[GROUNDED · config/env.ts:88-127]**

- `DEV_MOCK_DB=true` rejected when `NODE_ENV=production`
- `DATABASE_URL` required unless DEV_MOCK_DB or `NODE_ENV=test`
- `JWT_SECRET` required and ≥32 chars in production

## 7. Operational design

### 7.1 Maintenance mode

**[GROUNDED · middleware/maintenance.ts, app.ts:54]** Global write-freeze controlled by `MAINTENANCE_MODE` env. Per `sdd-infrastructure-migration.md §4.1`, used during cutover windows.

### 7.2 Mock DB mode

**[GROUNDED · db/mock.ts, env.ts:86]** `DEV_MOCK_DB=true` swaps the singleton DB to an in-memory mock for local dev. Production startup refuses.

### 7.3 Graceful shutdown

**[GROUNDED · index.ts:41-58]** SIGTERM/SIGINT close server, log, then `process.exit(0)`. 10s timer forces exit.

### 7.4 Migrations

**[GROUNDED]** 8 SQL files in `apps/api/src/db/migrations/`. Generated via `bun --filter api db:generate`. Applied via `db:migrate`.

## Naming Patterns Observed

### Files — CONSISTENT (kebab-case)
43 hyphenated vs 1 camelCase file under `apps/api/src` (e.g. `dynamic-auth.ts`, `admin-refresh.ts`, `namespace-validation.ts`, `visibility-guard.ts`). Co-located tests use `<name>.test.ts` throughout.

### Routes vs services — MOSTLY CONSISTENT (plural route, singular service)
- Routes plural: `teams.ts`, `packs.ts`, `subscriptions.ts`, `webhooks.ts`, `categories.ts` ✔
- Services singular: `team.ts`, `subscription.ts`, `category.ts`, `license.ts` ✔
- Exceptions: services `packs.ts`, `constructs.ts`, `skills.ts`, `signals.ts` are plural — two conventions coexist in `apps/api/src/services/`.
- Pair split: routes `creator.ts` AND `creators.ts` (publishing vs public profiles) — intentional but easy to confuse.

### Router export names — INCONSISTENT
`apps/api/src/app.ts:8-28` imports two styles: bare (`health`, `auth`, `oauth`, `dynamicAuth`) vs suffixed (`subscriptionsRouter`, `packsRouter`, `constructsRouter`, +14 more). One convention should win (suffixed is the majority).

### DB naming — CONSISTENT
35 `pgTable` definitions: TS camelCase const → snake_case SQL (`teamMembers` → `team_members`, `lastKnownRegistry` → `last_known_registry`). Enums end `Enum` (16 defined, schema.ts:30-129 + inline). Index names prefixed `idx_` (e.g. schema.ts:615 `idx_packs_category`).
